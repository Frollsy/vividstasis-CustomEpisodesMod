# Custom Episodes Mod · 剧情写作手册

给 *vivid/stasis* 写**自己的剧情**，用游戏原版的文本框、立绘、音效和演出效果播放。
你只需要写一个 JSON 文件，不需要写代码、不需要重新打包模组。

- 模组名：**Custom Episodes Mod**（模组目录 `mods/custom_episodes/`）
- 剧集目录：游戏目录下的 **`Custom Episodes/`**
- 入口：主界面选中 **NODE FLOWCHART** 按钮 → 按住 **Shift** 再按 **Enter**（调试用 **F9**）

---

## 0. 一分钟了解

| 你想要的效果 | 对应写法 |
|---|---|
| 一句对白 | `{ "who": "sat", "text": "……" }` |
| 旁白 | `{ "kind": "narration", "text": "……" }` |
| 换背景 / 换 BGM | `{"kind":"bg","value":"bg_tk_ikebukuro"}` / `{"kind":"bgm","value":"bgs_story_night"}` |
| 立绘出现 / 换表情 | `{"kind":"portrait","who":"sat"}` |
| 立绘移动 / 翻转 / 淡入淡出 | `move` / `flip` / `portrait_fade` |
| 音效、闪白、黑屏转场 | `se` / `flash` / `fade` |
| 定时停顿 | `{"kind":"delay","ms":800}` |
| 整屏文字（信件、独白） | `{"kind":"fullscreen"}` … `{"kind":"fullscreen_end"}` |
| 高清 CG / 高清背景 | `{"kind":"cg","value":"sp_cg_ep50","res":6}` |
| 自己的图片当画面 / 立绘 | `{"kind":"cg","value":"images/title.png","res":6}` |
| 视频过场（mp4） | `{"kind":"video","value":"video/op.mp4"}`（见 6.5） |
| 结束回主界面 | `{"kind":"end"}` |
| 在**谱面里**放剧情 | `story.json` 放到谱面文件夹，`.vsm` 里写 `custom_episode` 开始、`custom_episode_next` 逐句推进（见第 13 节） |

中文**不需要**手塞空格来换行：模组会按对话框宽度自动折行（见第 4 节）。

## 1. 安装与入口

### 1.1 前提

- 游戏本体 *vivid/stasis* + **vividstasisModLoader**（模组加载器）
- 想显示中文，需要你已经装好**中文字体补丁**：本模组全程使用游戏自己的字体，
  原版字体没有中文字形，没装补丁时中文会显示成方框或空白

### 1.2 模组装在哪

把 `custom_episodes` 整个文件夹放进加载器的 `mods/` 目录，然后运行一次
`vividstasisModLoader.exe` 即可：

```
vividstasisModLoader/
├── vividstasisModLoader.exe
└── mods/
    └── custom_episodes/          ← 整个文件夹放进来
```

### 1.3 剧集装在哪

放在**游戏目录**（和 `data.win` 同一个目录）的 `Custom Episodes/` 里，**每个剧集一个子文件夹**：

```
vividstasis/
├── data.win
└── Custom Episodes/
    ├── 我的第一集/
    │   └── story.json          ← 必须有这个名字
    └── 另一集/
        └── story.json
```

- **不要再重新打包模组**：选择器每次打开都会重新扫描目录，内容在你按下 Enter 进入时才读取
- 文件夹名只用英文/数字/下划线最稳（`my_first_episode`），中文标题写在 JSON 的 `title` 里
- 子文件夹里除了 `story.json` 之外的文件会被忽略
- 剧集列表按**文件夹名**排序

### 1.4 打开选择器

| 操作 | 说明 |
|---|---|
| 主界面选中 **NODE FLOWCHART**，按 **Shift + Enter** | 正常入口 |
| **F9** | 调试快捷键，只在主界面有效 |
| **↑ / ↓** | 选择剧集（打开后立刻可用） |
| **Enter**（或 Z、或你设置的确认键） | 进入选中的剧集 |
| **ESC**（或你设置的取消键） | 关闭选择器，回到主菜单 |

> 打开选择器的那一下按键不会立刻生效：模组会等 Enter / Shift / Z 松手之后才开始接受确认，
> 所以 Shift+Enter 不会"一开就自动进去"。

选择器上显示的内容：

```
CUSTOM EPISODES
Custom Episodes/ : 3 / 4 ready          ← 可用剧集数 / 总文件夹数
  示例：警局的一分钟  (52)                ← 标题（括号里是步骤数）
  我的第一集  (120)
Custom Episodes Mod 示例   52 steps      ← 作者 + 步数
演示外部剧情文本、自动换行、立绘、音效……   ← 简介（最多两行，放不下会以 … 结尾）
UP/DOWN  Enter play  ESC back
```

列表里灰色带 `[no story.json]` / `[story.json parse error]` 的文件夹表示暂时不可用，
选中后按 Enter 会在下方显示不能加载的原因。

## 2. 第一个可运行的剧集

在 `Custom Episodes/hello/story.json` 里写入：

```json
{
  "title": "我的第一集",
  "author": "你的名字",
  "description": "一句话介绍。",
  "bg": "bg_tk_ikebukuro",
  "bgm": "bgs_story_night",
  "characters": {
    "sat": { "display_name": "Saturday", "color": "c_aqua", "portrait": "sat_neutral" }
  },
  "lines": [
    { "kind": "location", "value": "池袋" },
    { "kind": "time", "value": "8:30 PM" },
    { "kind": "narration", "text": "夜色刚刚落下来。" },
    { "kind": "portrait", "who": "sat" },
    { "who": "sat", "text": "这段剧情完全是我自己写的。" },
    { "who": "sat", "text": "`c{think}连颜色标记也照常用。" },
    { "kind": "end" }
  ]
}
```

保存后回到游戏主界面，Shift+Enter → 选中 → Enter，即可播放。

> **JSON 格式提醒**：不能写注释、不能有多余的逗号；字符串里的换行要写成 `\n`，
> 引号要写成 `\"`。文件用 **UTF-8** 保存（记事本选 UTF-8 即可）。

## 3. JSON 字段参考

### 3.1 顶层字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `title` | 否 | 选择器里显示的标题，缺省用文件夹名 |
| `author` | 否 | 选择器下方显示的作者/来源，超长会截断 |
| `description` | 否 | 选择器下方的简介，最多显示两行 |
| `bg` | 否 | 开场背景（精灵资产名） |
| `bgm` | 否 | 开场 BGM（声音资产名） |
| `episode_name` | 否 | 章节标签，会写进游戏的 `last_episode_name`（影响暂停界面显示），结束后自动还原 |
| `characters` | 否 | 角色表，供 `who` 引用 |
| `lines` | **是** | 步骤数组，按顺序执行 |
| `wrap` | 否 | `false` = 关闭自动换行（默认 `true`） |
| `width` | 否 | 自动换行的宽度，单位像素，默认 `308` |
| `id` | 否 | 给剧集起个内部标识，模组不读它，方便你自己管理 |

### 3.2 characters 里的字段

| 字段 | 说明 |
|---|---|
| `display_name` | 名字框里显示的名字，缺省用 key 本身 |
| `color` | **名字框颜色**，必须是 GameMaker 颜色常量：`c_aqua`、`c_orange`、`c_red`、`c_white` … |
| `portrait` | 立绘精灵资产名，如 `sat_neutral`、`sat_frown`、`kot_ad_panic`；也可以是自定义图片（见第 7 节） |
| `expressions` | 可选。表情别名表：`{ "happy": "sat_happy" }`，供 `change` / `expression` 使用（见 5.3） |
| `x` / `y` | 立绘默认坐标，缺省 400 / 140 |
| `scale` | 立绘缩放，缺省 `0.14` |
| `facing` | `true` = 朝右，缺省朝左 |

引用角色时用 key：

```json
{ "who": "sat", "text": "用 key 说话。" }
```

### 3.3 lines 支持的指令

**文本类**

| `kind` | 字段 | 说明 |
|---|---|---|
| 省略 或 `line` | `who`, `text`, `speed`, `wrap`, `width` | 对白。`who` 省略 = 无名框；`speed` 1 = 原版速度，越小越慢（`2` 更快） |
| `narration` | `text`, `speed`, `wrap`, `width` | 与 `line` 相同，只是可读性更好 |
| `narrator` | `value` | 直接把名字框设成任意文本（不改说话人） |
| `clear` | — | 清空文本框 |
| `wait` | — | 只等玩家按确认，不显示新文本 |
| `delay` | `ms` | 定时等待，毫秒 |

```json
[
  { "kind": "narration", "text": "旁白。" },
  { "kind": "line", "speed": 0.5, "text": "说得慢一点。" },
  { "kind": "wait" },
  { "kind": "delay", "ms": 1200 }
]
```

**立绘类**

| `kind` | 字段 | 说明 |
|---|---|---|
| `portrait` | `who`, 可选 `portrait`/`expression`/`x`/`y`/`scale`/`facing` | 让立绘出现；已有同角色立绘时改为换图**并按 x/y 重新定位** |
| `change` | `who`, `portrait` 或 `expression`, 可选 `bounce`(缺省 true) | **只换表情**：保持当前位置 / 缩放 / 朝向，不重新定位（等价原版的 `sat.change(sat_smile)`） |
| `bounce` | `who`, 可选 `mode`(1 从下弹 / 2 从上落) | 只做一次弹跳小动作，不换图（等价原版的 `sat.bounce()`） |
| `move` | `who`, `x`, `y`, `time`(帧, 缺省 40), `flip` | 移动到新坐标，`flip` = 移动时翻身 |
| `flip` | `who`, `bounce`(缺省 true) | 原地翻身 |
| `portrait_fade` | `who`, `from`(1), `to`(0), `time`(帧, 60) | 透明度渐变，用来淡入淡出 |
| `hide` / `show` | `who` | 隐藏 / 重新显示某个立绘 |
| `portrait_clear` | — | 移除全部立绘（换场时常用） |

```json
[
  { "kind": "portrait", "who": "sat" },
  { "kind": "portrait", "who": "kot", "portrait": "kot_ad_panic", "x": 100 },
  { "kind": "move", "who": "sat", "x": 100, "time": 40, "flip": true },
  { "kind": "portrait_fade", "who": "sat", "from": 1, "to": 0, "time": 30 },
  { "kind": "portrait_clear" }
]
```

**声音类**

| `kind` | 字段 | 说明 |
|---|---|---|
| `se` | `value`, 可选 `gain` | 播放音效，`gain` 1 = 原音量 |
| `bgm` | `value` | 换 BGM（会停掉上一首） |
| `bgm_gain` | `to`(0~1), `time`(毫秒) | 当前 BGM 音量渐变 |
| `bgm_stop` | 可选 `fade`(毫秒) | 停止 BGM，给了 `fade` 就淡出 |

```json
[
  { "kind": "se", "value": "shatterfx" },
  { "kind": "bgm_gain", "to": 0.25, "time": 800 },
  { "kind": "bgm_stop", "fade": 600 }
]
```

**画面类**

| `kind` | 字段 | 说明 |
|---|---|---|
| `bg` | `value` | 换背景 |
| `tint` | `value`, 可选 `from`/`to`/`time` | 设置剧情色调（色幕）；只给 `value` 时是瞬时复位，等同原版写法 |
| `fade` | `to`, `color`(缺省 0 黑), `time`(帧), `wait` | **黑屏转场**：`to` 1 = 淡到色幕、0 = 淡回画面；`from` 默认接当前透明度，所以"淡出→换背景→淡入"不用自己写 `from` |
| `flash` | `alpha`, `color`(缺省白), `time`(帧) | 闪屏 |
| `resolution` | `value` | 房间渲染倍率：`1` = 原版（等同复原），`4` / `5` / `6` 是原版剧情用过的值 |
| `highres` | `value` | `o_bg` 是否按"拉伸铺满整屏"的方式绘制高清图（见 6.4） |
| `hidegui` | `value` | 是否隐藏左上角的地点 / 时间 / 日期 |
| `cg` | `value`, 可选 `res`(缺省 6)、`hidegui` | **一条搞定高清画面**：调倍率 + 拉满背景 + 可选藏 HUD |
| `location` | `value` | 左上角地点 |
| `time` | `value` | 左上角时间 |
| `date` | `value` | 左上角日期 |

```json
[
  { "kind": "fade", "color": 0, "to": 1, "time": 20, "wait": true },
  { "kind": "bg", "value": "bg_wm_nightstreet" },
  { "kind": "fade", "to": 0, "time": 20, "wait": true },
  { "kind": "flash", "alpha": 0.6, "time": 30 },
  { "kind": "date", "value": "November 18th, 2022" }
]
```

**视频类**

| `kind` | 字段 | 说明 |
|---|---|---|
| `video` | `value`，可选 `volume` / `scale` / `skippable` | 全屏播放一段 **mp4** 过场；播完（或玩家按确认跳过）之后剧情继续。详见 6.5 |

```json
[
  { "kind": "video", "value": "video/op.mp4" },
  { "kind": "narration", "text": "影像结束了，剧情继续。" }
]
```

**整屏文本**

| `kind` | 说明 |
|---|---|
| `fullscreen` | 切到游戏原版**全屏文本框**（信件、日记、大段独白）；之后的对白自动进全屏框 |
| `fullscreen_end` | 退出全屏文本框，回到普通对话框 |

```json
[
  { "kind": "fullscreen" },
  { "kind": "narration", "text": "亲启：这一整段会用全屏文本框显示。" },
  { "kind": "narration", "text": "全屏模式下每段都要按一次确认键。" },
  { "kind": "fullscreen_end" }
]
```

**流程类**

| `kind` | 说明 |
|---|---|
| `end` / `goto` / `abort` | 结束本集，回到主界面 |

> 目前没有分支选项（原版剧情本身也几乎不用），`goto` 与 `end` 等价。

## 4. 文本与排版

### 4.1 自动换行（默认开启）

游戏原版引擎**只在空格处折行**，所以官方中文版的正文明明是中文却到处塞着空格
（例如 `"……去探索 这座城市。"`）。本模组会在把文本交给原版文本框之前自己按宽度折行：

- 按 **308 像素**（原版对话框宽度）逐字测量，中文**不用**再写空格
- 英文单词不会被劈成两半（优先在最后一个空格处断开）
- 收尾标点（`。，、！？：；）》」` 等）不会被挤到行首
- 正文一个字符都不会增删，`` `c{...} `` 之类的标记也不会被拆开

```json
{ "kind": "narration", "text": "这一段故意不写任何空格也不写换行符，完全交给模组按对话框宽度自动断行，读起来和官方剧情一样自然。" }
```

### 4.2 手动换行

想自己控制断行位置，直接写 `\n`：

```json
{ "kind": "narration", "text": "第一行到这里结束，\n第二行从这里继续。" }
```

自动换行和手动 `\n` 可以混用。

### 4.3 宽度与开关

| 字段 | 位置 | 说明 |
|---|---|---|
| `width` | 顶层 / 单行 | 换成别的宽度（像素）。短句排版可以设小一点，如 `160` |
| `wrap` | 顶层 / 单行 | `false` = 完全交给原版引擎（会恢复成"只在空格处折行"） |

```json
[
  { "kind": "narration", "width": 160, "text": "窄一点，断行更早。" },
  { "kind": "narration", "wrap": false, "text": "这一行不做自动换行。" }
]
```

### 4.4 富文本标记（原版自带）

| 标记 | 效果 |
|---|---|
| `` `c{名字} `` | 换文字颜色，16 种：`red` `white` `aqua` `think` `black` `dawn` `wkeeper` `sat` `alli` `tsuki` `setsuki` `kisho` `chiyo` `kot` `eri` `miri` |
| `` `e{wave} `` | 波浪效果 |
| `` `e{jitter} `` | 抖动效果 |
| `` `e{rcolor} `` | 彩色闪烁 |
| `` `e{normal} `` | 恢复正常 |
| `` `r `` | 把颜色和效果一起还原 |
| ` `` ` | 显示一个反引号本身 |

```json
[
  { "kind": "narration", "text": "`c{think}（心里想的话）`c{white}，说出口的是这句。" },
  { "kind": "narration", "text": "`e{jitter}颤抖的文字`e{normal}恢复正常。" }
]
```

> 换色之后记得切回来，否则后面整段都会保持那个颜色。
> 注意这里用的是**文字调色板的名字**，和 `characters` 里的 `color`（`c_aqua` 这类）不是一回事。

## 5. 立绘

### 5.1 坐标系

游戏内部画面是 **320 × 180**，横坐标越大越靠右：

| 位置 | x 参考值 |
|---|---|
| 画面最左 | 0 |
| 三人并排 | 70 / 150 / 250 |
| 两人并排 | 100 / 220 |
| 单人偏右 | 250 |
| 默认（半个身子在右外侧） | 400 |
| 从右侧入场（先在画面外） | 520 |

纵向 `y` 一般在 **140 ~ 160** 之间（140 = 站得靠上，160 = 靠下/更近）。

```json
[
  { "kind": "portrait", "who": "kot", "x": 520, "y": 150, "facing": true },
  { "kind": "move", "who": "kot", "x": 250, "time": 40 }
]
```

### 5.2 常用套路

```json
[
  { "kind": "portrait", "who": "sat", "x": 520 },
  { "kind": "move", "who": "sat", "x": 250, "time": 40 },
  { "kind": "flip", "who": "sat" },
  { "kind": "change", "who": "sat", "portrait": "sat_happy" },
  { "kind": "portrait_fade", "who": "sat", "from": 1, "to": 0, "time": 30 },
  { "kind": "hide", "who": "sat" },
  { "kind": "portrait_clear" }
]
```

- 同一个角色反复调用 `portrait`：第二次起是**换图 + 按 x/y 重新定位**，不会叠出两个立绘
- **只换表情**（不动位置）请用 `change`，见 5.3

### 5.3 表情切换（change / bounce）

对白里最常见的动作就是"换个表情继续说话"，原版写作 `sat.change(sat_smile)`。对应写法：

```json
[
  { "kind": "portrait", "who": "sat", "x": 250 },
  { "kind": "change", "who": "sat", "portrait": "sat_happy" },
  { "who": "sat", "text": "直接写资产名也可以。" },
  { "kind": "change", "who": "sat", "portrait": "sat_frown", "bounce": false },
  { "kind": "bounce", "who": "sat" }
]
```

| 指令 | 说明 |
|---|---|
| `change` | 只换精灵：**位置 / 缩放 / 朝向都不动**。`bounce` 缺省 `true`（和原版 `.change(spr)` 一致，会小小弹一下），写 `bounce: false` 就是无声换图 |
| `bounce` | 只做一次弹跳，不换图；`mode` 1（缺省，从下方弹起）/ 2（从上方落下） |

**表情别名（推荐）**：角色表里可以写一张 `expressions` 表，把长资产名收成短名字：

```json
{
  "characters": {
    "sat": {
      "display_name": "Saturday",
      "color": "c_aqua",
      "portrait": "sat_neutral",
      "expressions": {
        "happy": "sat_happy",
        "angry": "sat_angry",
        "think": "sat_think"
      }
    }
  },
  "lines": [
    { "kind": "portrait", "who": "sat" },
    { "kind": "change", "who": "sat", "expression": "happy" },
    { "who": "sat", "text": "别名表让正文短很多。" },
    { "kind": "change", "who": "sat", "expression": "think" }
  ]
}
```

`expression` 的解析顺序：

1. 别名表 `expressions` 里有 → 用它
2. 别名里带 `_` 或 `.`（例如 `sat_smile`、`images/sad.png`）→ 当作完整名字直接用，不查表
3. 都没有 → 用角色默认立绘的**前缀**拼：默认 `sat_neutral` + 别名 `happy` → `sat_happy`

> `change` 也可以用在一个还没上场的角色上：那时它按 `portrait` 的规则把立绘创建出来
> （用角色表的 `x` / `y` / `scale` / `facing`），所以可以拿它当角色的第一次登场。

- `portrait_fade` 只改透明度，隐藏之后可以用 `show` 回来（透明度和 `visible` 是两回事）
- 想整体清场（换场景）用 `portrait_clear`
- 立绘名字写错不会崩，但那个立绘会被静默跳过；先用 `asset-names.md` 查名字

## 6. 声音与画面

### 6.1 音效与 BGM

```json
[
  { "kind": "bgm", "value": "bgs_story_rain" },
  { "kind": "se", "value": "sfx_songsel_beginsong", "gain": 0.6 },
  { "kind": "bgm_gain", "to": 0.2, "time": 800 },
  { "kind": "bgm_gain", "to": 1, "time": 800 },
  { "kind": "bgm_stop", "fade": 600 }
]
```

`gain` / `to` 是音量倍率（1 = 原音量，游戏里的设置音量仍会再乘一次）。

### 6.2 黑屏转场（换场必备）

```json
[
  { "kind": "fade", "color": 0, "to": 1, "time": 20, "wait": true },
  { "kind": "portrait_clear" },
  { "kind": "bg", "value": "bg_tk_ikebukuro" },
  { "kind": "location", "value": "池袋" },
  { "kind": "fade", "to": 0, "time": 20, "wait": true }
]
```

- `to: 1` 把画面淡到色幕（`color` 0 = 黑），`to: 0` 再淡回画面
- `wait: true` 表示"等这次渐变放完再继续"，转场才不会抢帧
- `time` 单位是**帧**（60 帧 ≈ 1 秒）

### 6.3 闪白、色调与时间地点

```json
[
  { "kind": "flash", "alpha": 0.6, "color": 16777215, "time": 30 },
  { "kind": "tint", "value": 0 },
  { "kind": "location", "value": "种子岛警局" },
  { "kind": "time", "value": "10:04 AM" },
  { "kind": "date", "value": "November 18th, 2022" }
]
```

### 6.4 高清画面 / 高清 CG（进阶）

游戏房间平时按 320×180 渲染，用大图当整屏画面时会被压得很糊。原版剧情放高清 CG 时是这样做的
（`ss_c1_e46_1` 等 12 处）：

```gml
o_cutsceneConductor.hideGui = true;      // 藏掉左上角地点/时间
set_resolution_multiplier(6);            // 房间按 6 倍分辨率渲染
o_bg.highres = true;                     // 背景改成"拉伸铺满整屏"
o_bg.sprite_index = sp_49bg_ikebukuro;   // 用大图当画面
... 场景结束 ...
reset_resolution();
```

模组把这一整套暴露成了四条指令，最省事的是 `cg`：

```json
[
  { "kind": "cg", "value": "sp_cg_ep50", "res": 6, "hidegui": true },
  { "kind": "narration", "text": "这一段就是 6 倍分辨率下的高清画面。" },
  { "kind": "hidegui", "value": false },
  { "kind": "resolution", "value": 1 },
  { "kind": "highres", "value": false },
  { "kind": "bg", "value": "bg_tg_precinct_int" },
  { "kind": "narration", "text": "已经复原成原版分辨率。" }
]
```

| 指令 | 作用 |
|---|---|
| `{"kind":"cg","value":"<大图资产名>","res":6,"hidegui":true}` | 一条完成：调倍率 + 拉满背景 + 藏 HUD（`res` 缺省 6，`hidegui` 缺省不动） |
| `{"kind":"resolution","value":6}` | 只调倍率；`1` = 复原成原版 |
| `{"kind":"highres","value":true}` | 只控制背景是否"拉伸铺满"；关掉就是按图片原生尺寸绘制 |
| `{"kind":"hidegui","value":true}` | 只控制左上角地点/时间/日期是否隐藏 |

要点：

- **倍率 > 1 时，普通背景必须配 `highres: true`**，否则 `o_bg` 会按图片原始尺寸绘制，
  只占屏幕左上角 1/n。模组已经做了兜底：`resolution` / `cg` 会自动把 `highres` 打开，
  `bg` 在倍率 > 1 时也会自动打开，所以你基本不用管它
- 倍率是**常驻**的（渲染表面被改大小了），所以高清段落结束后要复原。**剧集结束、启动失败、
  或从暂停菜单中途退出时，模组会自动复原**（倍率 / `highres` / `hidegui` 一起），
  但如果你在高清段落之后还要继续演普通内容，请像上面那样手动复原
- 可用倍率被限制在 1~8；原版用过 4、5、6
- 可用的大图资产名见 [`asset-names.md`](asset-names.md) 的"高清背景 / CG"一节
- 文字框在 GUI 层，不受房间倍率影响，所以高清画面上照样能正常显示对白

### 6.5 视频过场（mp4）

用 `video` 指令放一段全屏视频（片头、过场、结局动画）。**视频播完才继续**，玩家也可以按确认键跳过。

**放哪儿**：和 `story.json` 同级建 `video/` 文件夹，把 mp4 放进去——路径规则和外部音频完全一样。

```json
[
  { "kind": "bgm_stop", "fade": 400 },
  { "kind": "video", "value": "video/op.mp4" },
  { "kind": "bg", "value": "bg_tk_ikebukuro" },
  { "kind": "narration", "text": "影像结束了。" }
]
```

| 字段 | 缺省 | 说明 |
|---|---|---|
| `value` | 必填 | 视频路径。相对 `story.json` 所在文件夹；以 `/` 开头表示相对**游戏目录**，可以直接借用游戏自带的过场，例如 `/MOVIE/C1B_PY_LOOP.mp4` |
| `scale` | 自动 | 画面缩放倍数。不写时模组会**按解码后的画面实测尺寸**算出"铺满 320×180 又不变形"的倍数（640×360 → 0.5、320×180 → 1、1280×720 → 0.25），从第二帧起生效；写了 `scale` 就完全按你写的来 |
| `volume` | 游戏音乐音量 | 0~1。缺省跟随玩家的「音乐音量」设置（和原版过场一致） |
| `skippable` | `true` | 是否允许按确认键跳过 |

**格式要求（最容易踩的一条）**：必须是 **mp4（H.264 视频 + AAC 音频）**。播放走系统自带的解码器
（Media Foundation），有两类文件会**整段打不开**（没画面也没声音）：

- 视频编码不是 H.264 的：`H.265/HEVC`、`VP9`、`AV1` 都不行
- **音轨是 Opus 的**：OBS 默认录出来的 mp4 就是 `H.264 + Opus`，在游戏里会**整个文件播不出来**
  （不是"只有声音没有"）—— 请把 OBS 的「输出 → 音频 → 音频编码器」改成 **AAC**

已经有文件了不想重录？只把音轨转成 AAC 就行（视频流直接复制，不掉画质、很快）：

```
ffmpeg -i 原文件.mp4 -c:v copy -c:a aac -b:a 192k -movflags +faststart 新文件.mp4
```

模组对这类文件的处理：2.5 秒内既没画面、状态也没变成"正在播放"，就会跳过它并在文本框里提示
`[video failed to play] …（需要 H.264 + AAC 的 mp4）`，同时写进 `_modlog.txt`（`[video]` 开头的行），
不会卡住剧情。

**其它**

- 播放期间**文本框会滑出屏幕**、播完自动滑回来（对话框画在视频之上，不挪开就会挡住画面）
- 视频盖在最上层（深度 -999），播放前会清掉当前对白；过场结束后下一句对白重新出现
- 非 16:9 的视频按"等比缩放塞进画面"处理，左上角对齐（和原版做法一致）
- 视频音量是独立通道，不会再乘一遍游戏音量；想和 BGM 一起进出，就在前后用 `bgm_gain` / `bgm_stop`
- 找不到文件时不会静默失败：文本框会显示 `[video not found] 你写的路径`
- 谱面内剧情也能用 `video`（见第 13 节）：会盖住谱面、歌曲继续放，而且**默认不可跳过**
- 排查缩放问题：剧集顶层写 `"debuglog": true`，日志里会记 `movie: <文件> scale <初值>` 与
  `movie: surface 宽x高 -> vid_scale <实测值>`（**实测值才是最终生效的那个**；正常情况两者不同，
  因为初值只是给第一帧用的默认值）

## 7. 自定义图片与音频（用你自己的 PNG / OGG）

除了游戏自带素材，你还可以放自己的图片。模组会在**运行时**把图片文件读成精灵，所以整屏画面和立绘都能用。

### 放哪儿

图片放进你的剧集文件夹，直接放旁边或放进子文件夹都行：

```
Custom Episodes/我的剧集/
├── story.json
├── cg_title.png            ← "value": "cg_title.png"
└── images/
    ├── hero.png            ← "value": "images/hero.png"
    └── hero_smile.png
```

### 怎么引用

**看扩展名**：凡是写精灵名的地方（`bg` / `cg` 的 `value`、`portrait`、角色表里的 `portrait`），
只要名字以 `.png` / `.jpg` / `.jpeg` / `.gif` 结尾，模组就当成外部图片；否则照旧查游戏素材。
不需要额外字段，两种可以混用：

```json
[
  { "kind": "cg", "value": "images/cg_title.png", "res": 6 },
  { "kind": "bg", "value": "bg_tk_ikebukuro" },
  { "kind": "portrait", "who": "hero", "portrait": "images/hero_smile.png", "scale": 0.2 }
]
```

### 整屏图片

用 `cg`（高清）或 `bg`（普通）都行，图片会被**拉伸铺满** 320×180：

```json
[
  { "kind": "cg", "value": "images/cg_title.png", "res": 6, "hidegui": true },
  { "kind": "narration", "text": "自定义大图当整屏画面。" },
  { "kind": "resolution", "value": 1 },
  { "kind": "hidegui", "value": false },
  { "kind": "bg", "value": "bg_tg_precinct_int" }
]
```

- **建议出 16:9**（例如 1920×1080 / 1280×720 / 640×360），因为会被拉伸成 320:180；别的比例会变形
- 想要清晰就用 `cg`（内部会同时调分辨率与 `highres`）；用 `bg` 只适合分辨率等于原版时

### 自定义立绘

```json
{
  "characters": {
    "hero": {
      "display_name": "Hero",
      "color": "c_orange",
      "portrait": "images/hero.png",
      "x": 160,
      "y": 178,
      "scale": 0.25
    }
  },
  "lines": [
    { "kind": "portrait", "who": "hero" },
    { "who": "hero", "text": "我的立绘是外部 PNG。" }
  ]
}
```

- **必须自己写 `scale`**：`scale` 是倍率，`1` = 图片原始像素。想让立绘占屏幕高度的 90%（约 162 px），
  就用 **`scale = 162 ÷ 图片高度`**。例：图片高 720 → `scale = 162/720 ≈ 0.22`；图片高 1800 → `≈ 0.09`
- 不写 `scale` 会用角色表缺省的 `0.14`，图片一大就会糊满整屏，图片一小就几乎看不见
- 立绘按**底部中心**对齐到 `x` / `y`，和原版立绘一致（`y` 通常是 140~178，178 就是站在画面底边）
- 立绘**用带透明通道的 PNG**（PNG-32），否则会带一块底色
- 立绘一样支持 `move` / `flip` / `portrait_fade` / `hide` / `show` / `portrait_clear`

### 调试：不知道自己图片的尺寸？

在 story.json 顶层加 `"debugimages": true`，进入剧集时第一句对白会列出所有已加载图片的像素尺寸，
方便你算 `scale`：

```
playing custom episode: 我的剧集
`c{think}[images] images/hero.png 360x720, images/cg_title.png 1920x1080
```

### 找不到图片会怎样

- 进剧集时会**预加载**本集用到的全部图片（避免演到那一句才卡一下）
- 有图片读不出来（缺文件 / 拼错 / 格式不支持）时，第一句对白会出现红色提示：
  `[image not found] images/xxx.png`，然后剧情照常继续
- 同一张图只会读一次、解码一次；剧集结束、启动失败、或从暂停菜单中途退出时会自动释放

### 限制

| 项 | 说明 |
|---|---|
| 格式 | PNG / JPG / JPEG / GIF（GML `sprite_add` 的能力范围），推荐 PNG |
| 文件名 | 建议纯英文数字下划线，避免中文和空格（路径要交给游戏的文件 API） |
| 内存 | 每张图都会占纹理显存；一集里别塞太多超大图（例如十几张 4K） |
| 生效范围 | 图片只在**当前剧集内**有效，退出即释放；不能给主界面/选择器用 |
| 分辨率 | 整屏图一律拉伸到 320×180，非 16:9 会变形 |

> 模组维护者排查退出流程时可以在顶层加 `"debuglog": true`，它会把释放过程写进游戏目录的
> `Custom Episodes/_modlog.txt`。普通作者用不到，发布时建议关掉。

### 自定义音频（OGG）

自己的音乐/音效也能放进剧集里用。**只支持 OGG**（Vorbis）—— 游戏用的流式加载函数
`audio_create_stream()` 官方手册明确写了"仅限 OGG"，所以 `.wav` / `.mp3` 之类写了也不会生效，
模组会在开场用一句话告诉你"only .ogg works"。

**放哪儿**：和图片一样，放在剧集文件夹里（旁边或子目录都行）：

```
Custom Episodes/我的剧集/
├── story.json
├── bgm_night.ogg
└── audio/
    ├── theme.ogg
    └── door.ogg
```

**怎么引用**：凡是写声音名的地方（`bgm` / `se` 的 `value`、顶层 `bgm`），
只要以 `.ogg` 结尾就当作外部文件：

```json
[
  { "kind": "bgm", "value": "audio/theme.ogg" },
  { "kind": "narration", "text": "BGM 换成了外部 OGG。" },
  { "kind": "se", "value": "audio/door.ogg" },
  { "kind": "bgm_gain", "to": 0.2, "time": 800 },
  { "kind": "bgm_gain", "to": 1, "time": 800 },
  { "kind": "bgm_stop", "fade": 600 }
]
```

- 外部音频走**流式加载**：进剧集时预加载，`bgm_gain` / `bgm_stop` 照样可用
- 剧集结束、启动失败、或从暂停菜单中途退出时会**自动停止并释放**（手册明确要求销毁流，
  否则会泄漏）
- 合适的用途：BGM、环境音、持续音；同一个 OGG 同时当 BGM 和音效播放不一定成立，
  需要重叠时请准备两个文件
- 顶层 `"debugimages": true` 也会打印已加载音频的名称与时长，例如
  `` `c{think}[audio] audio/theme.ogg 42.7s ``

**格式与限制**

| 项 | 说明 |
|---|---|
| 格式 | **只支持 OGG**；`.wav` / `.mp3` / `.m4a` / `.flac` 会在开场提示不支持 |
| 文件名 | 同样建议纯英文数字下划线 |
| 内存 | 流式加载不占大块内存，但会占用文件句柄，退出剧集时统一释放 |
| 生效范围 | 只在当前剧集内有效 |

参考：[GameMaker 手册 - audio_create_stream](https://manual.gamemaker.io/monthly/en/GameMaker_Language/GML_Reference/Asset_Management/Audio/audio_create_stream.htm)
（"仅限 OGG"、以及用完必须 `audio_destroy_stream()`）

## 10. 排错

| 现象 | 原因 / 处理 |
|---|---|
| 选择器里看不到我的剧集 | 目录层级不对：必须是 `Custom Episodes/<文件夹>/story.json`，不能直接放在根目录 |
| 灰色 `[no story.json]` | 文件夹里没有 `story.json`（或名字拼错、大小写不符） |
| 灰色 `[story.json parse error]` | JSON 语法错：多余的逗号、漏引号、写了注释；用支持 JSON 校验的编辑器检查 |
| 按 Enter 提示 `Cannot load this episode` | 这个条目不可用，看选择器下方的具体说明 |
| 中文显示成方框/空白 | 没装中文字体补丁；模组用的是游戏自己的字体 |
| 文字冲出对话框右边 | 该行写了 `wrap: false` 或把 `width` 设得比 308 大；去掉即可恢复自动换行 |
| 换行位置不对 | 用 `\n` 手动控制，或把 `width` 调小 |
| 背景/立绘/音效没反应 | 资产名写错了会被**静默跳过**；照着 `asset-names.md` 核对拼写 |
| 出现 `unknown kind: xxx` | `kind` 拼错了（注意都是小写英文） |
| 立绘叠成两个 | 同一个 `who` 请一直用 `portrait` 指令；只有手写实例才会叠 |
| 转场一闪而过 / 背景突然出现 | `fade` 少了 `wait: true` |
| 标题/简介超出面板 | 标题会被截断到一行、简介截断到两行并以 `…` 结尾，这是有意的设计 |
| 剧情中途退出后进不去了 | 用 F9 或 Shift+Enter 重新打开选择器即可；模组每次回到主界面都会复位状态 |
| 想临时关掉 F9 | F9 只是调试入口，不影响正常游戏；发布版也可以保留 |
| 视频黑屏 / 没反应 | 编码不被系统解码器支持 | 转成 **H.264 + AAC 的 mp4**；OBS 录的要改音频编码器为 AAC（见 6.5） |
| 视频没声音但画面正常 | 这个文件本身没有音轨 | 用 MediaInfo 看音轨，或按 6.5 的 ffmpeg 命令重新封装 |
| 视频只显示左上角一块 / 周围有黑边 | 视频不是 16:9，或 `scale` 写错 | 删掉 `scale` 让模组自己量（见 6.5） |

## 11. 发布与分享

- 你只需要分享**你自己的剧集文件夹**（里面有 `story.json`），玩家把它拖进
  `Custom Episodes/` 就能玩；模组本体由你另行提供
- 剧集目录和模组目录是**分开**的：模组更新、重新打包都不会动玩家的剧集
- 建议在 `description` 里写清语言、篇幅和注意事项
- 引用了别人写的剧集内容/立绘时请遵守原作与模组作者的约定

## 12. 已知限制

- **没有分支选项**（原版剧情本身也几乎不用），`goto` 与 `end` 等价
- 不写存档、不解锁成就、不推进 `story_progress`；一集播完回到**主界面**（不回流程图）
- 从暂停菜单**中途退出**也回主界面；暂停菜单第二个按钮的文字仍是游戏原版的「返回节点流程」
  （那是原版文案，模组不擅自改多语言文本），实际行为是回主界面
- 立绘只有"移动 / 翻转 / 换表情 / 透明度 / 隐藏"，没有任意缩放动画、没有差分逐帧动画控制
- 没有全屏文本框之外的逐字控制（只有 `speed`）
- 文字样式只能用原版那套 `` `c{...} `` / `` `e{...} `` 标记
- 中文显示依赖你的中文字体补丁；模组界面文案是英文（原版游戏没有内置中文字库）

## 13. 谱面内调用剧情（`custom_episode`）

剧情也可以**在谱面里触发**：歌曲照常播放，文本框浮在谱面上，对白按歌曲时间自动推进——
原版的 MEMORIES、SUPERNOVA 就是这么演的。这是**简易版**：只有对白和少量指令；立绘、图片、
高清 CG、转场这些属于剧情房间的东西在谱面里不可用。

### 放哪儿

把 `story.json` 放在**谱面同一个文件夹**里，和 `<难度>.vsc`、`<难度>.vsm`、`music.ogg` 并列：

```
Custom Songs/
└─ 我的曲子/
   ├─ ENCORE.vsc
   ├─ ENCORE.vsm        <- 在这里加一行（见下）
   ├─ story.json        <- 谱面内剧情
   ├─ audio/mysfx.ogg   <- 可选：谱面内剧情用的音效（路径相对 story.json）
   └─ music.ogg
```

### 怎么触发

在 `.vsm` 里加 gimmick 行（行格式见 Custom Songs Mod 的说明）。**谱面内剧情是 beat 驱动的**：
`custom_episode` 在它所在的 beat 开始并显示第 1 步，之后**每个 `custom_episode_next` 推进一个 step**
（`line`/`narration` 显示后不再按毫秒自动换行，而是等下一次触发）。

```
!obj: obj_custom_gimmick
120,0,linear,_,_,custom_episode,-1          ; beat 120：开始，显示第 1 句
128,0,linear,_,_,custom_episode_next,-1     ; beat 128：第 2 句
136,0,linear,_,_,custom_episode_next,-1     ; beat 136：第 3 句
```

- 想让某句在某一拍出现，就把触发写在那拍 ✓（支持小数拍，如 `145.5`）
- `line` / `narration` 自带 `dwell`（毫秒）时，那一句改回**定时**；顶层写 `"chart_dwell": 2000`
  会把整篇的台词都变回定时推进
- `delay` 永远是定时；`wait` 不带 `ms` 时也是"等下一次触发"
- 触发到达时如果这一句还在打字，会**立即补全并推进**（跟拍优先）
- 剧情没在等触发时的触发会被**丢弃并记日志**（`%LOCALAPPDATA%\vividstasis\Custom Episodes\_modlog.txt`，
  `[chart] next ignored: …` 会写明原因：剧情没在跑 / 视频正在播 / 正在 delay）
- `video` 播放期间的触发会被忽略（视频是实时播放的，剧情不能穿过去），把触发写到视频结束之后即可
- 想让多个谱面共用一份剧本：在 `.vsm` 里写 `!story: 相对游戏目录的路径.json`，它会覆盖同目录的 `story.json`
- `!obj` 可写可不写（默认 `obj_base_gimmick`，写 `obj_custom_gimmick` 也一样）

### 支持哪些指令

| 指令 | 谱面里的行为 |
|---|---|
| `line` / `narration` | 对白 / 旁白；`who`、`text`、`speed`、`wrap`、`width` 照旧，`characters` 里的 `display_name` 照旧。**默认等下一次 `custom_episode_next` 才换行**，写了 `dwell` 才改成定时 |
| `narrator` | 直接把名字框设成任意文本 |
| `clear` | 清空文本框 |
| `wait` | 等下一次触发；写了 `ms` 就改成定时毫秒 |
| `delay` | 定时停顿，毫秒（不受触发影响，这期间的触发会被丢弃并记日志） |
| `se` | 音效；`value` 可以是游戏资产名，也可以是相对 `story.json` 的 `.ogg` |
| `video` | 播放 mp4 过场，**会盖住谱面**，歌曲继续放；谱面内默认**不可跳过**（写 `"skippable": true` 才用确认键跳）；播放期间的触发会被忽略并记日志 |
| `bgm_gain` / `bgm_stop` | 调整 / 停止当前 BGM（在谱面里那就是歌曲本身，慎用） |
| `end` / `goto` / `abort` | 结束这段谱面内剧情（歌继续放） |

**不支持**的指令会被**跳过**，并把种类写进日志
`%LOCALAPPDATA%\vividstasis\Custom Episodes\_modlog.txt`（游戏把日志写在存档目录里，
不在游戏安装目录）：
`portrait`、`change`、`bounce`、`move`、`flip`、`portrait_fade`、`hide`、`show`、`portrait_clear`、
`bg`、`cg`、`highres`、`resolution`、`hidegui`、`fullscreen` / `fullscreen_end`、`flash`、`fade`、
`tint`、`location`、`time`、`date`、`bgm`。

### 时间怎么推进（beat 驱动 / 定时两种）

谱面内默认是 **beat 驱动**：`line` / `narration` 显示后停在那里，直到下一次 `custom_episode_next`
把它推到下一步。想精确定时的地方用下面两种写法：

- 顶层 `"chart_dwell": 2500`：**整篇**台词都变成"停留 2500 毫秒 + 打字时间"的定时模式
- 单行 `{"kind":"narration","text":"…","dwell":3000}`：只让这一句定时
- `{"kind":"delay","ms":800}`：显式停顿（不受触发影响；这期间来的触发会被丢弃并记日志）
- `{"kind":"wait"}`：等下一次触发；`{"kind":"wait","ms":800}`：定时 800 毫秒

打字速度在谱面内缺省是原版的一半（`speed` 0.5，约 50 字/秒）：谱面可以跑到 1000 fps，
沿用原版速度会快得看不见打字过程；想更快更慢就写 `"speed": 1` / `"speed": 0.25`。

对话框滑入/滑出固定按时长换算帧数，停稳位置在 y=132——和原版谱面内剧情（MEMORIES / SUPERNOVA）一致；
`custom_episode` 那一拍会**立刻显示第 1 句**（不额外等框滑进来）。

### 谱面内排错

日志在 `%LOCALAPPDATA%\vividstasis\Custom Episodes\_modlog.txt`（无条件写，不需要开 `debuglog`）：

| 日志里看到 | 说明 |
|---|---|
| `[chart] start …/story.json` | gimmick 命中了，剧本也读到了；后面应该跟 `finished` 或 `stop (…)` |
| `[chart] no story folder for this chart (not a custom song?)` | 谱面目录没读到（不是自定义曲，或 `chart_path` 缺失） |
| `[chart] could not start …` | `story.json` 不存在 / 不是合法 JSON / `lines` 是空的 |
| `[chart] step not available in a chart, skipped: xxx` | 这段剧情里用了谱面内不支持的指令（见上表），该步被跳过 |
| 完全没有 `[chart]` 行 | gimmick 名没命中：检查 `.vsm` 里是不是 `custom_episode`、`.vsm` 是否和 `.vsc` 同名同目录 |
| `[chart] next -> step N` | 触发推进成功，N 是**新**步骤的序号（1 起） |
| `[chart] next ignored: not waiting for a trigger (delay / box slide in)` | 剧情正在 `delay` 或还没到等待点，这次触发被丢弃 |
| `[chart] next ignored: a cutscene is playing` | 视频期间触发被忽略（把触发写到视频之后） |
| `[chart] next ignored: no story is running` | 还没 `custom_episode` 或剧情已结束 |
| 剧情只显示第一句就不动了 | `.vsm` 里漏写 `custom_episode_next`（每句都要一个触发） |
| `stop (left the song)` | 玩家中途退出 / 重开 / 歌曲结束，文本框已被收掉 |

### 限制

- 只在**自定义曲目**里有效：需要 Custom Songs Mod 读取 `.vsm`；gimmick 名要靠 Custom Gimmicks Mod
  的按名字解析才能命中（装了它最稳）
- 不影响谱面判定，也不写存档；玩家中途退出 / 重开歌曲时文本框会自动收掉
- 一段剧情还在演的时候又触发一次（写了多条 gimmick，或者玩家按了快重开键）会**从头重演**，
  而不是排队等待
- 谱面内**不能等玩家按键**（歌在放，等按键就卡住了），需要停顿请用 `delay`
- 谱面内剧情和剧情房间里的剧集是两套状态，互不影响；同一时间只有一个在播
